## Внутри каждого урока

- **Понятный вход:** цель, необходимые знания и данные для работы.
- **Визуальная карта:** обложка направления и отдельная схема по содержанию конкретного ноутбука.
- **Пошаговый разбор:** навигация и объяснения рядом с исходными ячейками.
- **Практика:** вопросы для самопроверки, небольшой эксперимент и критерий успеха.
- **Контекст результата:** исходные авторские ссылки, сохранённые графики и аудио, ограничения перед новым запуском.

Иллюстрации помогают разобраться в материале. Архивные выводы относятся к прежним экспериментам; оформление не означает, что все 65 работ заново запущены или готовы к применению.

## Первый законченный эксперимент

Начните с [небольшой нейросети на NumPy](ML/reproducible_mlp_xor_numpy.ipynb). Она создаёт синтетические данные, использует раздельные train/validation/test и нормализацию только по обучающей выборке. Данные скачивать не нужно; ключи и облачные сервисы не требуются.

1. Откройте ноутбук в Jupyter или Colab и прочитайте цель и схему.
2. Запустите ячейки по порядку на CPU с установленным NumPy.
3. Проверьте результат на отложенном тестовом наборе.
4. Измените один параметр и запишите, что изменилось и почему.

После этого выберите одну архивную работу и сначала проверьте её раздел «Источники и ограничения».

[Workflow проверок](.github/workflows/notebook-audit.yml) сохраняет отчёт об оформлении. Зелёный результат **не подтверждает выполнение 65 архивных экспериментов**, их метрики или доступность внешних данных.

Для проверки в отдельном окружении Python 3.12:

```bash
python -m pip install -r requirements-design.txt
python tools/check_notebooks.py
python tools/verify_notebook_design.py --repo-root .
python tools/check_notebooks.py --run-example
```

`requirements-design.txt` задаёт окружение проверки оформления и стартового примера. Архивные TensorFlow/Keras-работы требуют отдельного подбора зависимостей; общий `requirements.txt` не гарантирует их совместимость.

## Что важно перед запуском архива

Сохранённый материал может обращаться к личным дискам, недоступным наборам данных и старым версиям библиотек. Команды установки, удаления файлов или публикации нужно читать и адаптировать вручную. Длинные текстовые журналы местами сокращены с явной ссылкой на исходный архив; графики и аудио сохранены.

Из обновлённых файлов убраны найденные значения доступа и чужая глобальная настройка автора Git. Удаление из текущей версии не отзывает ранее раскрытый ключ и не очищает историю: владельцу ключа нужно отозвать его у провайдера.

Числа точности в старых названиях — исторические подписи, а не независимо подтверждённые результаты. Материалы `medicina/` — учебные исследовательские задания, не клинические диагностические инструменты. Авторство и ссылки исходных материалов сохраняются; права на сторонние данные, код и изображения проверяются отдельно. Отсутствие LICENSE не означает разрешение на любое использование.
