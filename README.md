## Что есть в каждом уроке

- Понятное название, конкретная цель и необходимые знания.
- Три коротких действия: объяснение, исполняемый код и проверка результата.
- Иллюстрации ученицы, человека-ментора и бота после каждого шага.
- Небольшой самостоятельный эксперимент с подсказкой и критерием успеха.
- Границы примера, разбор исправлений и ссылка на полную исходную работу.

Мира, Данил и Пикс — вымышленные персонажи. Их реплики объясняют материал; они не являются отзывами людей или результатами автоматического анализа твоего кода. Числа и графики вычисляются при запуске ячеек, а проверки `assert` помогают заметить расхождение.

## Короткий урок и большая исходная работа

Основной маршрут объясняет конкретную идею на обозримом примере. Если для упрощения использован другой набор данных или небольшая модель, это явно указано в разделе «Что разбираем» и ограничениях. Одна свёртка на NumPy не выдаётся за полную обученную CNN, а искусственные данные — за реальные наблюдения.

[Полные исходные работы закреплены в неизменяемом архиве](https://github.com/safal207/students/tree/2e46691c24aabcb6e71852e07254a0965fc3a59b). В каждом ноутбуке есть прямая ссылка на его исходный файл и сохранённые авторские источники. Старые результаты и числа в исторических именах файлов относятся к тем экспериментам; новый короткий маршрут не подтверждает их автоматически. Архивные медицинские исследования сохранены для учебного разбора; упражнения не являются диагностическими инструментами.

## Что проверяет CI

[Workflow](.github/workflows/notebook-audit.yml) запускает проверки на Python 3.12 в трёх группах: **001–022**, **023–044** и **045–066**.

| Проверка | Что подтверждает |
| --- | --- |
| Содержание и структура | Рецепт, название, три шага, реакции, встроенные картинки, ссылки и согласованность кода |
| Реальное выполнение | Подготовка и все три шага каждого выбранного урока в новом Python-ядре на CPU |
| Проверки внутри уроков | Форма данных, границы, расчёты и другие условия `assert` соответствующего примера |
| Сохранённые результаты | Выводы связаны с проверенной версией рецепта и кода |

В каждом запуске сохраняется отчёт `reports/lesson-validation.json`; в GitHub Actions он доступен как артефакт `lesson-validation-<группа>`. Исполненные ячейки сохраняются в рабочую копию ноутбуков. CI не публикует эти изменения автоматически.

Статус относится к конкретному коммиту и указанной группе уроков. Он не подтверждает выполнение полных архивных TensorFlow/Keras-экспериментов или их исторические метрики.

<details>
<summary>Запустить проверки локально или пересобрать уроки</summary>

Используй отдельное окружение Python 3.12. Прямые зависимости зафиксированы в [requirements-lessons.txt](requirements-lessons.txt).

```bash
python -m pip install -r requirements-lessons.txt
python tools/check_lessons.py --repo-root .
python tools/check_lessons.py --repo-root . --execute
```

Для одного урока:

```bash
python tools/check_lessons.py --repo-root . --execute --ids 018
```

Источники уроков находятся в `tools/lesson-recipes/`, иллюстрации — в `assets/lesson-characters/`. После изменения источников сборка создаёт свежие ноутбуки без результатов; следующий запуск выполняет код и сохраняет реальные выводы:

```bash
python tools/build_lessons.py --repo-root .
python tools/check_lessons.py --repo-root . --execute
```

Окружение коротких уроков не предназначено для запуска всего исторического архива. Полные исследования имеют собственные данные и зависимости, описанные в исходных работах.
